# OCR 内部

[图片与 PDF 文字识别](/zh/guide/use/ocr)讲的是开启、隐私与面向操作者的限制。本页记录这些行为背后的实现细节。

## 页面判定

没有可靠的文档级“扫描版 PDF”标志，所以 Nanofile 逐页判断：

- `lopdf` 提取该页的文本层。非空白字符达到 32 个的页面是文本页，保留该文本。
- 低于该阈值的页面按扫描页处理。受限的 OCR worker 用纯 Rust 的 `hayro` 栅格化该页，再用 PP-OCRv6 识别。
- 两类页面按原页序合并。文本页保留文本层；扫描页用 OCR 文字，OCR 为空时回退到该页很短的文本层。

之前由 OCR 生成的文本层，只要每页都达到阈值，就会被当作文本信任，不再重复识别。文本很多、带插图的页面也按文本页处理；插图里的字不会读。这是有意的取舍：不检查 Producer，不数文件内图片，也没有单独的标志。

只有矢量字形、没有文本层的页面不在保证范围内：渲染器没有嵌入字体，这类页面可能渲染不出可读的字形。目标就是位图扫描页。

## 渲染与上限

- `hayro` 只被要求渲染需要像素的页面；PDF 文本层仍由 `lopdf` 读取。
- PDF 整份读取，最多 32 MiB；文本层受现有 2000 页提取上限约束。
- OCR 没有单独的页数上限：worker 逐页渲染候选页，直到 150 秒软截止（低于 profile 的 180 秒硬超时）或达到 8 MiB 文字上限。长扫描件因此只索引一部分；剩余页要等重建索引，backfill 不会续跑。
- PNG、JPEG、WebP、BMP、GIF、TIFF、ICO 由 OCR worker 解码。HEIC、HEIF、AVIF 先经配置的 `storage.ffmpeg_path` 解出一帧。
- 单张图片最多 32 MiB，每张图片或每个 PDF 页最多识别 300 行文字；文字上限与文档提取相同，为 8 MiB。
- 一个四分类模型把横放或倒置的扫描页/照片转正（90°、180° 或 270°）。一个二分类模型翻转单行倒置的文字。其他角度、手写、很小的字、低对比度照片和装饰字体都会降低准确率。
- 多栏页面按简单的自上而下顺序读取。搜索不受影响，但高亮片段里的顺序可能与原页面不同。
- 视频、Office 文档内嵌图片、压缩包内文件不做 OCR。

## 模型

PP-OCRv6 tiny（检测与识别）与 PP-LCNet 页面、文本行方向分类器在受限的 OCR worker 中通过纯 Rust 的 `tract` 运行时执行。模型编译进二进制，运行时不下载。模型为 Apache-2.0；来源、revision 与限制见 `server/models/MODEL_CARD.md`。

PDF 扫描页由 `hayro` 渲染，它是纯 Rust 的 PDF 栅格化器（Apache-2.0 OR MIT）；PDF 文本层仍由 `lopdf` 读取。

## 保存的数据

只保存识别出的**文字**，作为该文件的正文进入全文索引。不按文件保存图片裁剪、页面位图、文本框、置信度、方向判断结果或模型状态。

索引目录**不加密**，文字里可能包含姓名、地址或证件号码。能读取该资料库的人就能搜到这些文字；资料库权限本身不变。关闭 `[ocr]` 只停止新的 OCR，已经写入索引的文字会保留到重建索引为止（重新索引资料库，或调用 `POST /api2/reindex/`）。
