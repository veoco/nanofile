# Windows 服务与桌面托盘

**适合谁：** 想要托盘菜单或无人值守服务的 Windows 用户。**前置条件：** Windows，以及安装开机服务所需的管理员权限。

Windows 的托盘与开机服务见本页；Linux 与 macOS 上让服务随系统启动见[后台运行与自启动](/zh/guide/deploy/running-in-background)。

`--features tray` 构建的二进制带系统托盘菜单：

- **登录启动** —— 写入当前用户的启动项，登录后启动。
- Windows 上的**开机启动（管理员）** —— 自动启动服务，并让开启它的账户在登录时看到托盘；即下面的内容。
- 打开网页，
- 打开配置文件，
- 退出。

## 开机启动（管理员）

**开机启动（管理员）**会向 SCM 注册一个自动启动的服务，**开机即启动，不需要任何人登录**，适合无人值守的机器。命令行 `nanofile service install` 等价。从托盘启用时还会写入「登录启动」项；命令行安装则由首次运行托盘时补上。

勾选后会弹出管理员授权提示；取消授权不会产生任何改动。弹授权提示**之前**会先检查这个服务是否真能跑起来（配置文件、各个数据目录、日志目录、`ffmpeg`、端口）。过不了的检查会点名并拒绝注册，需要注意的项会先让你确认。

### 服务账号

**服务以 `NT SERVICE\Nanofile` 运行**——每服务独立的虚拟账号：无密码、独立 SID、不与他人共用身份，访问网络时以机器账号身份。这是微软推荐的做法（而不是 `LocalSystem`）。

- `LocalSystem` 仍可通过 `--account system` 指定，用于虚拟账号拿不到权限的目录场景。
- 也支持 `--account network` 或具体账号。指定具体账号时需要 `--password`、`--password-stdin` 或交互输入密码。

账号会写在确认框里、由 `service status` 报告，并在每次启动时记入日志。

### 目录权限

安装时会**为该账号授予**各个数据目录、日志目录与配置文件的修改权限（服务身份默认什么都访问不了）。卸载服务时会回收。如果有目录它写不了，会在注册之前拒绝，而不是等到下次开机才失败。

## 开机启动包含登录托盘

注册服务时，会同时为开启它的那个 Windows 账户写入「登录启动」项；服务注册期间菜单里该项显示为**勾选且置灰**。托盘只连接到服务器，从不占用端口，所以装服务不会让你失去托盘。

卸载服务会一并移除该项，Nanofile 不再自动启动。想改为在当前会话里启动服务器，勾选「登录启动」。

服务对所有用户生效，但托盘项是按 Windows 账户的：其他账户第一次运行 Nanofile 时会补上自己的那一份。

## Windows 自己的启动开关

任务管理器的“启动”选项卡和“设置 → 应用 → 启动”可以在不删除启动项的情况下把它关掉。这个开关会被尊重：被关掉的项显示为未勾选，点「登录启动」可以恢复；服务注册期间该项平时是勾选且置灰的。

## 路径与修复

两种注册都记录绝对路径，因此会"活过"一次移动。

- 登录启动项指向的可执行文件或配置文件已不存在时，下次启动托盘会自动改为指向当前这份；服务注册在位时，缺失的登录项也会被补写。健康项、或本版本读不懂的项一律不动。
- 属于其他安装的登录项不动，只在菜单里提示。
- 服务注册指向的目录已不存在时，确认框会明确说明再改写。

显式指定的配置文件不存在（`--config` 或 `NANOFILE_CONFIG`）会**拒绝启动**，而不是悄悄退回内置默认值。

## 何时生效

**从下次系统启动开始生效**：当前这份托盘程序继续提供服务，菜单会显示服务"已注册但未运行"。不让服务立刻接管端口，是因为 Windows 下刚关闭的连接会停留在 `TIME_WAIT` 数分钟，新进程绑定同一端口会失败。

服务注册之后，可以随时从菜单「启动/停止 Windows 服务」（管理员）或 `nanofile service start|stop` 启停它。

## 升级

运行中的服务会锁住自己的可执行文件，所以替换前先停掉它：用托盘里的「停止 Windows 服务」，或在管理员终端执行 `nanofile service stop`。替换二进制后，再从托盘或 `nanofile service start` 启动；重启机器也会在下次开机时用新文件启动。

原地覆盖（路径不变）不需要重新注册。把安装目录换到新位置则需要：下次启动托盘时，菜单会点名旧的注册并提示改指；登录托盘项会自动改指。

## 服务运行时

服务运行时手动打开托盘程序会进入"客户端模式"：不再启动第二份服务，会显示当前是谁在提供服务，且**点「退出」只关闭托盘**，服务继续运行。要停止服务器，用「停止 Windows 服务」（管理员）；它会在下次开机，或点「启动 Windows 服务」时回来。

该菜单同样可以安装/卸载服务，以及打开网页和配置文件。

## 通知与弹窗

每次托盘启动会发一次桌面通知（启用登录启动时也就是每次登录一次；Windows 通知中心、Linux 通知服务；macOS 构建不发通知）。它只是提示，没有开关。

弹窗只用于需要决定或失败的情况；一次操作不会叠两个确认框，一次失败也不会叠两个错误框：

- **开机启动**：一个确认框列出后果、预检提示，以及托盘以管理员运行时将要注册登录项的 Windows 账户；然后是 UAC，最后是一个成功提示。失败时只有一个带技术原因的对话框。
- **启动/停止 Windows 服务**：除 UAC 外没有确认；成功由状态行体现，只有失败才弹框。
- **登录启动**：平时不弹；写入失败用通知提示（Windows/Linux；macOS 只写日志）。
- **致命启动错误**：配置读取失败、首次初始化超时、因服务占用地址而拒绝启动、启动后服务器失败、托盘创建失败，都会在有桌面时弹框：Windows 是消息框，macOS 用 `osascript`，Linux 用 `zenity`/`kdialog`（或 `notify-send`）。
- 状态行与 tooltip 在 Windows/Linux 上每 5 秒重新探测；macOS 在点击托盘图标时刷新，因此打开的那一次菜单可能还是旧状态。

完整原因始终在可执行文件旁的 `nanofile.log`；弹窗里是截短后的内容。

## 日志

服务模式没有桌面，因此不会显示托盘图标；日志写入二进制旁的 `nanofile.log`。

服务启动时会记录账号、可执行文件、配置文件、工作目录，以及每一条目录检查的结果。预检不过时会直接拒绝启动（退出码 2），而不是稍后抛一个不带路径的错误。

## 验证

- 托盘图标存在，菜单能打开网页界面与配置文件。
- 菜单显示服务器状态；服务注册期间「登录启动」是勾选且置灰的。
- `nanofile service status` 报告注册状态与账号。
- 下次开机后，服务在无人登录的情况下运行；日志里写明账号与配置文件路径。
