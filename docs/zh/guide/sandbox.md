# 沙盒

所有解析用户提供内容的功能都在独立子进程中运行，带内存上限、CPU 上限与墙钟超时，不在服务器进程内：

- 搜索索引的文档正文提取，
- 图片缩略图，
- 媒体缩略图（经 `ffmpeg`），
- EXIF 与头像处理。

子进程先自我限制、再读请求，然后报告它实际建立的保护；服务器按这份报告决策，而不是按它提出的要求。

## 它保护什么

- **资源边界是唯一强制项。** 建立不了它的子进程会被父子两侧同时拒绝——解析炸弹与死循环正是这套机制要防的失败。一台连资源边界都建立不了的主机，上面这些功能一律不运行。
- **文件、网络与进程三层是纵深防御**，防的是解析器自身的漏洞（这些解析器都是纯 Rust，唯一会启动的外部程序是媒体 helper）。
- **不防的**不会被断言为成立：内核漏洞，以及以同一用户运行的其他进程。

这些机制按平台建立，不是配置项——能建立什么由操作系统决定。

## 对你的影响

- **媒体缩略图需要 `ffmpeg`。** 路径由 `storage.ffmpeg_path` 指定；保存它会立即重新解析这份授权，下一次媒体请求就用新的二进制。
- **沙盒关着时这些功能不运行**，也不会退回服务器进程内解析。关闭期间跳过的文档记为可重试状态，重新打开后会被重新索引——因此"关一阵再开"不会留下永久搜不到的文件。
- **想知道本机实际给了什么，看管理后台的「沙盒」页**：每个 profile 一组，每项保护一行，并带状态徽章。每行说明这一项是什么、是否就位、有多重要、缺了意味着什么；**资源边界**标为"必选"。页面上不会做总结或打等级——行里写着的就是全部结论。
- **某些项在你的平台上根本无法建立**，这属于平台固有而非配置问题：macOS 的解析器 profile 拒绝 `fork`；Windows 的 Job Object 没有句柄与文件大小上限的等价物；媒体 worker 按设计必须启动程序，因此"启动程序"这一项对它记为**不适用**。页面都会在旁边注明。

## 总开关

`[sandbox] enabled` 是总开关。关闭后：

- 上述功能一律不运行，
- 不会回退到服务器进程内解析，
- 关闭期间跳过的文档记为可重试状态，而不是对其字节下的结论，因此重新打开后会被重新索引。
