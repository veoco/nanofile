# 沙盒

**适合谁：** 需要了解沙盒对搜索、缩略图与可选媒体功能有什么影响的运维人员。**前置条件：** 一个管理员账号。

所有解析用户提供内容的功能都在独立子进程中运行，带内存上限、CPU 上限与墙钟超时，不在服务器进程内：

- 搜索索引的文档正文提取，
- 图片缩略图，
- 媒体缩略图（经 `ffmpeg`），
- EXIF 与头像处理，
- 自动人物标签的人脸检测，
- 全文索引的图片与扫描版 PDF 文字识别（`[ocr]`）。

子进程先自我限制、再读请求，然后报告它实际建立的保护；服务器按这份报告决策，而不是按它提出的要求。

## 它保护什么

资源边界是唯一强制项。文件、网络与进程三层是纵深防御，防的是解析器自身的漏洞。不防的东西不会被断言为成立：内核漏洞，以及以同一用户运行的其他进程。各平台的机制与 probe 见[沙盒内部](/zh/dev/sandbox)。

## 对你的影响

- **媒体缩略图需要 `ffmpeg`。** 路径由 `storage.ffmpeg_path` 指定；保存它会立即重新解析这份授权，下一次媒体请求就用新的二进制。HEIC/HEIF/AVIF 照片的人物标签和 OCR 也用同一个 helper 先解码。
- **沙盒关着时这些功能不运行**，也不会退回服务器进程内解析。关闭期间跳过的文档记为可重试状态，重新打开后会被重新索引——因此"关一阵再开"不会留下永久搜不到的文件。
- **想知道本机实际给了什么，看管理后台的「沙盒」页**：每个 profile 一组，每项保护一行，并带状态徽章。每行说明这一项是什么、是否就位、有多重要、缺了意味着什么；**资源边界**标为"必选"。人物标签那一组只在功能开启时才实测：关闭时它只显示状态并指向开关，因为检测器的 probe 要跑一次前向。OCR 那一组同理，并且要求索引与 `[ocr] enabled` 都开启：它要加载四个模型，没人启用的功能不该付 probe 的代价。页面上不会做总结或打等级——行里写着的就是全部结论。
- **某些项在你的平台上根本无法建立**，这属于平台固有而非配置问题：macOS 的解析器 profile 拒绝 `fork`；Windows 的 Job Object 没有句柄与文件大小上限的等价物；媒体 worker 按设计必须启动程序，因此"启动程序"这一项对它记为**不适用**。页面都会在旁边注明。

## 总开关

`[sandbox] enabled` 是总开关。关闭后：

- 上述功能一律不运行，
- 不会回退到服务器进程内解析，
- 关闭期间跳过的文档记为可重试状态，而不是对其字节下的结论，因此重新打开后会被重新索引。

## 验证

- 打开**系统设置 → 沙盒**；资源边界一行标为必选且已就位。
- 每个已启用的 profile 都显示状态徽章；关闭的功能会指向它的开关。
- 上传一个文档与一张缩略图；两者都工作，或者页面点名缺失的机制。
