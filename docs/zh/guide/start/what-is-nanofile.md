# 什么是 Nanofile？

Nanofile 是一个单 Rust 二进制的自托管文件同步与分享服务。它实现 Seafile 同步协议和官方桌面端、移动端客户端使用的 HTTP 接口，并自带网页界面。不需要另装 seaf-server + seahub。

**适合谁：** 想用官方 Seafile 客户端、但希望服务端更简单的人，小团队，或家庭实验室。**不适合谁：** 需要 Seafile 全部功能、需要多节点集群，或需要原样导入现有 Seafile 数据目录的部署。

## 它是什么

- **一个二进制。** 服务端、网页界面和后台 worker 都是同一个可执行文件，不需要 PHP、Python 或 Java 运行时。
- **Seafile 客户端。** 官方桌面端与移动端可以直接连接并同步资料库。
- **网页界面。** 在浏览器里浏览、预览、上传、下载、收藏、搜索、查看动态和从回收站恢复。
- **分享。** 带密码、过期时间和查看次数的分享链接，以及向资料库匿名上传的上传链接。
- **账号与安全。** 两步验证、受信设备、登录失败锁定、会话、同步令牌和 API 密钥。
- **管理后台。** 用户、配额、注册、邮件、分享策略、系统设置和后台任务。
- **受限解析。** 文档、图片、EXIF、媒体、人脸检测和 OCR 解析都在有界子进程中运行，不在服务器进程内。
- **可选的媒体功能。** 自动人物标签，以及图片和扫描版 PDF 的 OCR；两者默认关闭。

## 与 Seafile 的兼容性

兼容性是路由层和协议层的承诺，不是每个功能都逐字节一致的承诺。权威列表见
[Seafile API 兼容性](/zh/reference/api/compatibility)；协议规则见
[Seafile 兼容性](/zh/dev/protocol)。

### 能用的部分

- 官方 Seafile 桌面端与移动端可以登录并同步。
- 客户端使用的同步协议、旧版 `/api2/` 接口面和 `/api/v2.1/` 接口面。
- WebDAV、分享链接、上传链接、API 密钥、配额和两步验证。
- 网页界面与管理后台。

### 没有实现的部分

- 完整的 seahub 替代品：Seafile 管理界面、插件和 Seafile Pro 的全部功能都没有复刻。具体缺口以兼容性页为准。
- 按文件夹分享。分享的单位是资料库。
- Wiki、SeaDoc 和 Seafile 的 OCR metadata 接口。
- Seafile 数据目录导入。兼容性页比较的是 HTTP 接口，不是存储格式；迁移意味着把文件重新同步或重新上传到一个新的 Nanofile 实例。

## 核心概念

| 术语 | 含义 |
|---|---|
| **资料库** | 存储、分享和权限的单位。Seafile 客户端把它叫作 repository。 |
| **同步** | 客户端通过 Seafile 同步协议让本地副本与服务器保持一致。 |
| **块** | 文件内容按内容寻址的块存储；数据库保存资料库和文件结构。 |
| **提交（commit）** | 资料库文件树的一次快照，带历史记录和与 Seafile 兼容的 commit id。 |
| **分享链接 / 上传链接** | 让没有账号的人下载或向资料库上传的公开链接。 |
| **API 密钥 / WebDAV 密钥** | 给脚本、第三方工具或 WebDAV 挂载用的受限凭据，不是账号密码。 |
| **加密资料库** | 客户端加密的资料库。服务器永远拿不到资料库密码。 |
| **全文索引** | 从文档中提取的正文，存放在数据目录旁，可从网页界面搜索。 |
| **沙盒** | 解析不可信内容的受限子进程。 |

## 限制

- **一个进程、一个 SQLite 数据库。** 当前架构没有内置集群或多节点模式；本指南假设一个数据目录对应一个服务器。
- **加密资料库在客户端解密。** 网页界面不能预览或下载它们，匿名上传链接也不能指向它们。
- **WebDAV 不服务加密资料库**，因为 WebDAV 无法携带资料库密码。
- **OCR 与人物标签是可选项，而且有边界。** 两者都依赖沙盒，也都有准确率和格式限制；见各自页面。
- **Seafile 的功能缺口是真实存在的。** 不要因为 Seafile 有某个接口或界面功能就假设 Nanofile 也有；先查兼容性页。
- **没有 Seafile 数据目录导入。** 从 Seafile 迁过来意味着把文件重新同步或重新上传到 Nanofile。

## 环境要求

- Linux、macOS 或 Windows 的发布归档，或已发布的 Docker 镜像。见[选择部署方式](/zh/guide/start/choose-deployment)。
- 服务用户可读写的目录。默认是二进制旁的 `data/`。
- 主密钥。release 构建没有它会拒绝启动。
- 要走 HTTPS 就在前面放反向代理；见 [HTTPS 与反向代理](/zh/guide/deploy/https-and-reverse-proxy)。
- 可选：`ffmpeg`，用于媒体缩略图，以及在做人脸检测和 OCR 前解码 HEIC/HEIF/AVIF。

## 适合谁

如果你想要 Seafile 客户端、较小的自托管占用和网页界面，又不想维护 seaf-server + seahub，Nanofile 适合你。如果你需要 Seafile Pro 功能、按文件夹分享、多节点集群，或从现有 Seafile 安装做受支持的原位迁移，它不适合。
