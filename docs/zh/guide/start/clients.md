# 客户端接入

除了网页界面，还有三种方式把数据接进来：官方 Seafile 客户端做同步、WebDAV 挂载成网盘、API 密钥给脚本与第三方工具。

## 官方 Seafile 客户端

桌面端与移动端直接连 Nanofile，不需要另装 seaf-server + seahub。

**服务器地址**填客户端真正能访问到的那个地址，也就是 `server.site_url` 的值（见[安全](/zh/guide/admin/security)）。它不能只是"服务器上能打开的地址"：客户端会用同一份地址去取块、上传、生成链接，写错会表现为能登录但同步不动。

### 登录

在客户端里填邮箱和密码即可登录。客户端也可以走浏览器登录：它打开浏览器 → 你在网页里登录 → 确认页显示请求登录的**平台与设备名** → 确认后服务器签发令牌，客户端取回并完成登录。确认页刻意显示设备信息，这样你能认出不是自己发起的那一次。

### 两步验证

开启两步验证后，客户端登录会要求一次 6 位动态口令；勾选"信任此设备"后，这台设备在 **90 天**内不必再输。每台受信设备在**设置 → 会话与凭据**里单独列出，可以随时吊销。

### 同步令牌

每一次客户端登录都会留下一条同步令牌，在**设置 → 会话与凭据**里逐条列出并单独吊销。改密码会吊销该账号所有的同步令牌。

### 加密资料库

加密资料库只能在客户端创建，库密码也只在客户端输入——服务端没有这份密码，因此网页预览与下载、匿名上传链接都不能用于加密资料库。

## WebDAV

WebDAV 把资料库挂成普通网盘，适合不想装同步客户端、只想浏览与拷贝文件的场景。

- **地址：** `https://<站点>/dav/<资料库 id>/`。这个地址在资料库列表里打开某一行的**编辑**就有，旁边是复制按钮。
- **认证：** HTTP Basic——用户名是你的**邮箱**，密码是**该资料库的 WebDAV 密钥**。
- **密钥：** 在**设置 → API 密钥**新建，选择 WebDAV 预设（只读或读写）；资料库编辑框里也有直达入口。密钥只在创建时显示一次。
- **总开关：** `server.webdav_enabled`。关闭后所有 WebDAV 请求一律拒绝。
- **权限：** 你能读还是能写，跟随这个资料库对你的权限（只读或读写）。

能填 WebDAV 地址与 Basic 凭据的客户端都能用：Windows 的"映射网络驱动器"、macOS 的"连接服务器"、Linux 的 davfs2/gvfs，以及移动端的 WebDAV 应用。

**加密资料库不支持 WebDAV** —— WebDAV 没有办法传递库密码，因此带 WebDAV 能力的密钥不能绑到加密资料库上。

## API 密钥

API 密钥给脚本与第三方工具用，避免把账号密码交给它们。在**设置 → API 密钥**创建：

- **能力** —— 按用途勾选，或选一个预设（预设里包含 WebDAV 只读与读写）。写入类的能力在界面上单独标出。
- **范围** —— 全部资料库，或逐个资料库指定只读（`r`）／读写（`rw`）。
- **有效期** —— 从几天到永不过期。
- 密钥**只显示一次**；列表里能看到名称、创建时间、到期时间与上次使用时间，可改名、改有效期、吊销。

调用时把密钥放进 `Authorization` 头：`Authorization: Bearer <密钥>`（`Token <密钥>` 也可以）。

密钥管理界面只接受浏览器会话，因此**密钥不能再签发密钥**；改密码会吊销该账号的全部密钥。见[账号安全](/zh/guide/admin/account-security)。

## 连不上时

按顺序检查：

1. **地址** —— 客户端填的地址是否就是 `server.site_url`，并且客户端真能访问到它。
2. **TLS** —— 走 HTTPS 时用的是可信证书吗（自签名证书客户端会拒绝）。
3. **反向代理** —— 反代后面要设 `trusted_proxies`，否则所有客户端都会塌缩成代理地址，按 IP 的限流把它们塞进同一个桶。见[安全](/zh/guide/admin/security)。
4. **两步验证** —— 客户端是否提示要动态口令；先确认它提示的是口令，不是密码错误。
5. **日志** —— 服务端日志里的登录失败原因，见[维护与故障排查](/zh/guide/operate/maintenance)。

工作量证明（PoW）挑战只保护网页表单，客户端不会遇到它——它们不在浏览器里，无法求解。
